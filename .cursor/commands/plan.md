## Goal

Turn the spec into architecture and a small task list. Don't write product code.

## Sequence

1. Read the spec and the current codebase. Map modules, seams, and what depends on what.
2. Design deep modules: small interface, lots of implementation. Agree the test seams before any tests.
3. Slice vertically. Write small tasks with acceptance criteria. Save to `tasks/plan.md` (short planning phases) and `tasks/todo.md` (detailed specific tasks).
4. Draw a diagram only if a picture helps. Keep it small (5–9 parts).



## Rules

- Don't write product code. This is plan, not build.
- Don't skip seam agreement.
- Tasks stay small. Break anything that needs 5+ files or says "and."
