## Goal
Turn a raw idea into a sharp concept. Write a PRD when the direction is clear.

## Sequence
1. Restate the problem. Who is it for? What does success look like?
2. Offer a few real options. Pick one. Name the bets and what could kill it.
3. Write a one-pager: problem, direction, MVP, not-doing. Save to `docs/ideas/` only if they say yes.
4. If they want a spec, synthesize a PRD from what you already know. Save to `docs/requirements/`.
5. Draw a diagram only if a picture helps. Keep it small (5–9 parts).

## Rules
- Push back on weak ideas. Don't yes-machine.
- Don't skip "who is this for."
- Don't interview for the PRD — synthesize.
- Don't write code. This is research, not build.
